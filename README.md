# LAREX Action: SBB Binarization

[LAREX](https://github.com/OCR4all/LAREX/) action for image binarization using [sbbbin](https://github.com/jahtz/sbbbin).

To obtain a binarization model, refer to the [sbbbin documentation](https://github.com/jahtz/sbbbin/tree/larex-action/sbbbin#model).

## Deployment

### Environment

Create a `.env` file from the template and populate its values:

```bash
cp template.env .env
```

| **Variable**                     | **Default** | **Description**                                                                                                                                                                                         |
| -------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `NAME`                           | required    | Suffix of the container name (`larex-action-<NAME>`).                                                                                                                                                   |
| `PORT`                           | required    | Port on which the action's endpoints are exposed.                                                                                                                                                       |
| `LAREX_PROCESSOR_ID`             | required    | ID of this processor. Must match the processor ID LAREX sends in the headers of dispatch requests.                                                                                                      |
| `LAREX_DISPATCH_HMAC_SECRET`     | required    | Shared secret generated by LAREX, used to verify the signature of dispatch requests. Keep it private.                                                                                                   |
| `LAREX_ALLOWED_CALLBACK_ORIGINS` | required    | Comma-separated list of LAREX origins (scheme, host, port) the SDK accepts for callbacks, e.g. `https://larex.example.org`.                                                                             |
| `LAREX_ROUTE_PREFIXES`           | required    | Comma-separated route prefixes, e.g. `/kraken`, under which the `/dispatch` and health routes are additionally exposed (`/kraken/dispatch`).                                                            |
| `LAREX_SDK_TRANSPORT_DEBUG`      | `false`     | Set to `true` to log the SDK's communication with LAREX (pulls, heartbeats, downloads, uploads, retries, failures).                                                                                     |
| `ACTION_DEBUG`                   | `false`     | Set to `true` for debug-level worker logging; otherwise only info and above is logged.                                                                                                                  |
| `ACTION_MAX_CONCURRENT_RUNS`     | `1`         | Maximum number of runs processed at the same time per processor instance; further runs wait for a free slot. Every run starts its own worker process, so increase only after measuring host/GPU memory. |
| `ACTION_LOADING_TIMEOUT`         | `90`        | Maximum time in seconds a worker process may take to load (e.g. models). Applies to every worker start, including restarts after a page timeout. If exceeded, the whole action fails.                   |
| `ACTION_PROCESSING_TIMEOUT`      | `None`      | Maximum processing time per page in seconds, not including worker loading. `None` means no limit. What happens when it is exceeded is set by `ACTION_TIMEOUT_MODE`.                                     |
| `ACTION_TIMEOUT_MODE`            | `fail_page` | What happens when `ACTION_PROCESSING_TIMEOUT` is exceeded: `fail_page` fails only that page, restarts the worker and continues with the next pages; `fail_action` fails the whole action.               |
| `SBB_SUFFIX`                     | `.sbb.bin.png` | Suffix for output image file names.                                                                                           |
| `SBB_DEVICE`                     | `cuda`         | Compute device for inference. Supported: "cuda", "cpu".                                                                       |
| `SBB_MODEL_DIR`                  | required       | Directory containing trained pytorch (.pth) models.                                                                           |


### Docker/Podman Compose (Recommended)

Build and start the action:
```bash
docker compose build && docker compose up -d
```
